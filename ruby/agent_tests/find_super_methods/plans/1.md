# Ruby Find Super Methods — Test Plan

## Summary

This document describes the test coverage planned for the `ide_find_super_methods` Ruby handler. The tool is simpler than `ide_call_hierarchy` (no direction, depth, or recursive tree), so the test surface is smaller.

## Test Coverage

| # | Test file | Category | Scenarios | Fixtures needed |
|---|-----------|----------|-----------|-----------------|
| 1 | `fsm_01_basic_override` | Basic inheritance | Single-level class override, position in body, symbol lookup | `basic_inheritance.rb` |
| 2 | `fsm_02_mixin_override` | Mixin override | `include` module override, symbol lookup | `mixin_override.rb` |
| 3 | `fsm_03_deep_chain` | Deep hierarchy | 3-level chain, order verification, depth field | `deep_chain.rb` |
| 4 | `fsm_04_no_super` | No parent | Method with no superclass, top-level method | `no_super.rb` |
| 5 | `fsm_05_class_methods` | Class methods | `self.` method override, symbol lookup | `class_methods.rb` |
| 6 | `fsm_06_cross_file` | Cross-file | Super method in different file, symbol lookup | `cross_file/base.rb`, `cross_file/sub.rb` |
| 7 | `fsm_07_predicate_bang` | Special names | `?` and `!` suffix methods, symbol lookup | `predicate_and_bang.rb` |
| 8 | `fsm_08_edge_cases` | Edge cases | Empty body, singleton class, `extend`, `define_method`, empty file, nonexistent file, invalid position | `edge_cases.rb`, `empty.rb` (created at test time) |

## Comparison with call_hierarchy

| Aspect | call_hierarchy | find_super_methods |
|--------|---------------|-------------------|
| Direction | callers / callees | N/A (always upward) |
| Depth | Configurable (1-5) | N/A (all parents returned) |
| Tree structure | Recursive children | Flat array with depth |
| Test files | 8 | 8 |
| Fixtures | 21 `.rb` files | 10 `.rb` files (incl. subdirs) |
| Across files | Yes | Yes (cross_file) |
| Symbol lookup | Yes | Yes |
| Edge cases | Yes | Yes |

## How to run

1. Build and install the plugin: `./build-and-install.sh`
2. Open the project in IntelliJ with Ruby plugin
3. Follow the steps in `test_instructions.md` for each test file
4. Write results to `reports/` directory
